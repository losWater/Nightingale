# 虎码式翻页与句点残留修复 · 2026-09-27

用户最终要求取消句号翻页，使用虎码的减号／等号翻页。前一轮“无条件强制句号”只是未部署草稿，已撤回，不采用。

## 修改

- 单字方案取消 key_binder 的 default 预设导入，仅使用本方案显式绑定：减号上一页、等号下一页；逗号句号均不翻页。
- 停用 single_period 处理器，不再通过额外 Lua 强制提交句号。保留原生 punctuator 的中文句号 commit 行为。旧 Lua 文件留作历史，不再注册或作为新构建依赖复制。
- 将 single_prefix 从 ascii_composer/recognizer 之前移到 key_binder 之后。它仍负责有效前缀保护，但先让常规识别处理本次按键。
- 单字 schema 版本 single.6 → single.7。仅补丁修改本机 schema，不整包覆盖，不改字典、学习数据、形码或 V5。

## 复现及对照

只去掉默认翻页和旧句号处理器、但不改前缀顺序时，在隔离引擎中连续测试 `f.`、`f,`、`dv.`、`rj.`，最后一项可得到残留输入 `r.j.` 而没有提交；重复 `rj.` 可交替出现正常与残留。将前缀处理放到 recognizer/key_binder 后，同样序列全部正常。此对照支持处理顺序是这条已复现路径的原因；没有声称已覆盖用户所有偶发现象或确认引擎内部具体缓存实现。

真实虎码配置并非“所有场景无条件提交句号”：英文和 URL 仍可含点。本次按用户最后确认采用虎码式翻页和原生标点，不再实现前一条无条件强制句号草稿。Control+period 的中英文标点开关与虎码一致，保留；普通 period 无额外快捷绑定。
