# 夜桜（自然码版）：3.1 根与键位迁移（2026-10-13）

**2026-10-15 作者定名：ZR27 = 夜桜 1.0。**

目标（作者定）：用夜莺 3.1 的字根、拆分，音码换成自然码双拼；**在 3.1 的布局（NB46）上改，改动尽量小**。
留存版本：**ZR27**（相对 NB46 换键 27 组）——`yozakura/ZR27_layout.json`（扁平 {组: 键}，同 NB46_layout）、`yozakura/ZR27_换键.json`、`yozakura/ZR27_form.json`、`yozakura/夜桜_ZR27_普通单字表.txt`。2026-10-15 作者：自然码版布局定型。

工具箱（与夜莺同款六个视图）：`YZ_BRAND=yozakura/品牌.json .venv/bin/python release/make_toolbox.py ~/Downloads/夜桜_工具箱`。
`release/config.py` 读 YZ_BRAND 换名称、布局、码表；字根练习“只练改动过的根”对照夜莺 3.x（NB46），进度存 yozakura_memory_v1；工具箱名“夜桜嘤嘤工具箱”（作者 2026-10-15 定），Q 版形象 yozakura/形象/夜桜Q版.png（作者生成，替换页面里两处夜莺形象）。不设 YZ_BRAND 时夜莺工具箱输出不变（核对过逐字节一致）。

## 输入与复现

- 引擎输入（只换双拼，其余与 3.1 的 n30 相同）：
  `W=$(cat build/out/n30/weights.json); YZ_FIX=$PWD/data/inputs/一二简.json .venv/bin/python build/make_inputs.py zr31 "${W/\"xiaohe\"/\"ziranma\"}"`
  - `build/make_inputs.py`：非小鹤方案时，留给词的二码位（声母缩写，与双拼无关）让出本方案下单字二简的码。小鹤输入不受影响（核对过与 n30 一致）。
  - 退火用 `build/out/zr31m`：同上另加 `YZ_MOVE_BASE=$PWD/release/NB46_form.json`，换键代价改为相对 NB46。
- 出表：ZR27_form 跑引擎 encode → `build/make_plain_table.py <运行目录> <输出> ziranma`（`YZ_INP=zr31`，`YZ_MANUAL=yozakura/手动调整.json`）。
- 手动二简/三简（2026-10-15）：`yozakura/手动调整.json`，由夜莺 `data/inputs/手动调整.json` 逐条换算成自然码（同一对字在 ZR27 下仍撞同一码位，裁定原样照搬）。作者按全码手感逐对复核：型/形 不照搬（夜桜下型 xypz 3.8、形 xypf 3.6 难度相近，xyp 留给更常用的形，记在文件的“不照搬”里）；喂/味 两全码都因自然码 ei→z 多了 wz 小指干扰，喂仍更难，保持。最终码变 20 字（游/油、符/弗、圆/园、熟/署、喂/味、竹/筑、攻/工、激/济、浅/潜、附/夫 两两互换）；秦、远、勤、元本来就是。前1500 四码 114→116（工、型 失去三简）。夜莺以后新增手动调整，夜桜这边要同样换算。
- 门禁：`YZ_INP=zr31 YZ_SCHEME=ziranma .venv/bin/python release/check_table.py <表> 1`（check_table 新增 YZ_SCHEME）。
- 未套：出表阶段的简词让位与 ü 容错（字词表）。

## 过程

1. **NB46 原样转自然码**：全码重码、选重、四码不变（双拼只是换音节写法）；不过门禁的是字词撞①（3：依 借 亿）、撞③（15）。
   当量：形码管得到的读音（排除固定一二简）2→3 前500/1500 由 1.278/1.296 升到 1.297/1.315；1→2 基本不变；3→4 不变。
2. **邻域搜索**（`neighborhood/zr/greedy.py`）：5 组即过门禁，但选重、四码贴线。
3. **退火**（`anneal_run.py`，起点 NB46，换键代价 5/10/20 各 4 种子）：选 **mc20_s4**（换 12 组，选重 0、四码 119）。
   不限换键（代价 0，8 种子）换 77–91 组，形码成本最好 1.3438，不如邻域 29 组的 1.3392，手感也没变好 → **大改无回报**。
4. **精修**（`greedy.py`，起点 mc20_s4）→ 精修16组。
5. **当量拆分**（`decomp.py`）：与夜莺3.1 比，前1500 字均当量差 0.018，其中约 85%（0.0146）在 1→2，即自然码音节自身，换根改不了；2→3 多 0.0063，精修收回 0.0034。
6. 群友（鲸酱肉丝）建议：**扣掉自然码自带的大跨排、小指干扰后与小鹤比，不输即可；再在三码率、重码上找补。**
   - 第二轮（`polish2.py`）：全码代理手感 + 非独占 → 对测评站的全码重不对口。
   - 第三轮（`polish3.py`）：前1521 键位相关全码重 ×5、四码 ×1 → 三码 1025、四码 119，形部大跨仍 28。
   - 第四轮（`polish4.py`）：每步实际出表，按测评站字表前1500 字的实际最短码算形部手感，换键组数 ×1（可撤回不必要的换键）→ **ZR27**。

## 测评站口径（assess.tiger-code.com，《科学形码测评体系》，服务器端计算；以下由本地复算对上）

- 大跨排：形码盒子 ms；**小指干扰：同手小指键与无名指键连按**（本地复算 1/3/29 对站上 1/3/31）。均只数码内键对、取最短码。
- 全码重：区间内的字，其最长码与前 hi 字中另一字相同（夜莺3.1 复算 0/0/2 = 站上）。
- 4码/3码按测评站自己的字表；本地用形码盒子默认字频，个别数与站上略有出入。
- 汇总脚本：`neighborhood/zr/site_all.py`。
