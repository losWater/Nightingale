# 建议新增候选窗主题「智能ABC」（复古直角灰）

## 想法

现有九个主题都是圆角 + 现代配色。想补一个复古方向的：把候选窗做成智能 ABC 那个年代的样子——Win9x 系统灰、黑宋体、直角、藏蓝高亮。

除了怀旧，它还补上了一个现有主题没覆盖的维度：**九个内置主题的圆角全是非零**（`{5,5,5,5}`，赛博朋克是 `{10,0,10,0}`），没有一个是纯直角。直角本身就是一种很强的风格信号。

## 配色

```cpp
{0xff000000,0xffc0c0c0,0xff808080,0x66000080,2,{0,0,0,0}}   // 智能ABC
```

| 字段 | 值 | 来历 |
|---|---|---|
| foreground | `0xff000000` | 纯黑 |
| background | `0xffc0c0c0` | Win9x 的 3D Face，就是那身系统灰 |
| border | `0xff808080` | Win9x 的 3D Shadow，立体边的暗侧 |
| selection | `0x66000080` | Win9x 的 Active Title，那抹藏蓝 |
| borderWidth | `2` | 接近当年立体边的厚度 |
| corners | `{0,0,0,0}` | 直角 |

## 改动

`native/CandidateTheme.h`，数组 9 改 10，名字表末尾加一个：

```cpp
inline constexpr std::array<std::u16string_view,10> candidateThemeNames=
  {u"默认",u"通透",u"一般通透",u"迷雾",u"星夜",u"纸",u"粉",u"赛博朋克",u"清晨",u"智能ABC"};
```

`native/CandidateTheme.cpp`，同样 9 改 10，调色板末尾追加一行：

```cpp
static const std::array<CandidateTheme,10> themes={{
    ... 原有九行不动 ...
    {0xff000000,0xffc0c0c0,0xff808080,0x66000080,2,{0,0,0,0}}   // 智能ABC

```

## 三处需要你判断的地方

**一、选中色没有跟着前景色走。**九个内置主题的 selection 一律是「foreground 的 RGB + `0x48`」。这一版没有照办，用的是独立的藏蓝 `#000080`——那抹蓝正是这套风格最认得出的信号，跟着黑色前景走就没了。如果你希望保持全表一致，可以改成 `0x48000000`，但会损失不少味道。

**二、选中色的透明度是 `0x66` 而不是 `0x48`。**因为文字是叠在选中块之上画的，藏蓝在 `#C0C0C0` 上要够深才看得出来，又不能深到压住黑字。`0x66` 是试下来的平衡点：合成后约 `#7373A6`，黑字仍然清楚。

**三、`tests/theme_parity.py` 需要处理。**按 `THEMES.md` 的描述，它「从只读的原始源码里抽取全部九条调色板声明」来做对照。新主题在原始 WPF 源码里没有对应项，所以这个测试要么放宽到「前九条必须与原始一致」，要么给新增主题单独列白名单。这一条我没法替你决定，取决于你想让 parity 测试守住什么。

## 一个做不到的地方

Win95 的立体边其实是双色的——左上白、右下深灰。现在的 `CandidateTheme` 只有一个 `border` 颜色和一个 `borderWidth`，做不出来，所以这一版用单色暗侧灰近似。

不是非要不可，只是记一笔：如果哪天想支持这类拟物风格，`border` 扩成四条边各自的颜色就够了，不影响现有九个主题（四边填同色即可）。
