## 4. 已确定的码表和简词规则

### 4.1 单字与词的候选顺序

- 一个全码位置上的字最多给词让 **一个首选位**。
- 若有词占首选，则紧接着排列该码位的单字，之后再排其他词。
- 若该码位的单字没有简码，则单字整组优先，词不能抢首选。
- 四字及以上词按“全码词”参与同码词频比较。
- 鲸凉鹤原表的同码多重顺序可视为词频顺序。
- 去飞键后两个原码组合并的情况应单独审计候选顺序。

### 4.2 简词数量

- 默认“单字 + 简词”合计最多三选。
- 该位置已有单字时，通常最多保留两个简词；没有单字时最多三个简词。
- `lj` 等人工规定组例外。
- 二字简词撤简前先补全码。
- 三字及以上简词撤简时不补全码。
- 项目中的“无简词”通常指删除二、三字且不足四码的简词；四字及以上词不算简词，应保留标准四码。

## 10. 推荐接手顺序

1. 阅读本文件、根目录 `AGENTS.md` 和 `评估规则.md`。
2. 校验第 2.1 节三个基线文件的 SHA256，确认没有被其他进程改动。
3. 修正 `71\build_rime_no_short.py` 的三个已知问题。
4. 先将输出写入 `71` 的新目录和独立 schema ID，不覆盖 P70。
5. 静态检查 fixed、smart、native 三层：不存在多字二三码固定入口，也不存在来自旧 P70 的纯字母飞键四码入口。
6. 用 `rime_bench.exe` 对轻量版、主力版分别做空目录部署和正/负候选测试。
7. 生成 ZIP、SHA256 和 JSON 核验报告，再把结果交给用户。
8. 等用户恢复精力后，再处理含简词飞键：先出差异清单，人工复核后重跑 P64→P70 全平台流水线。

## 11. 操作纪律

- 所有新实验先写新编号目录或明确的 `实验/` 子目录；不要把试跑输出冒充正式文件。
- 修改前备份原文件，并记录 SHA256、条数和生成时间。
- 人工裁定 JSON 优先于自动词频和脚本默认顺序。
- 根集评估必须遵循 `AGENTS.md`：只有同音且首末根所属组都相同才算完整重码，不能用首根或末根单独相同的并集冒充重码总数。
- 每次跨目录实装后检查：裁定指针、无简词表、含简词表、拆分查询、工具箱、字根练习、平台包是否来自同一基线。
- 打包前必须完成格式核验、候选序核验、容量核验、压缩包 CRC、SHA256；Rime 还必须做真实引擎部署测试。
