## 0. 横切结论（先读这个）

1. **增量缓存一致性没有闭环**。libchai 的字词交叉缓存在增量路径会漏"只有简码变化"的字（C1）；而本应兜底的独立复算器 audit_cross_collision.py 三处口径偏离实现（G1-G3），常见配置下恒报 0 或恒有噪声。实现和门禁同时失效 ⇒ 漂移只能在退火收尾的全量重算警告里偶然现身。
2. **多音字没有单一口径**。同字同前两码（声调多音字：好/少/教/传…）的频率，polyphone_slot_audit 取 max、global_collision_audit 被"最后一行覆盖"（G6）、多个脚本默认 `rows[0]` 是主读音但 apply_reading_aliases 会把高频别名追加到队尾（P4，嗯现状实测 `[[0,'ngar'],[157982,'enar']]`）。"多音字修了好几轮还是多"的根源大概率是：每一轮修的是不同脚本里的不同口径。
3. **`排序序号` 是一次半途的迁移**。libchai 排序语义改了（lib.rs），report_word_collisions 适配了，audit_cross_collision 没适配（G2），交叉缓存的 `take_while(词长==1)` 对部分标注的资产会静默算错（C2）。建议：在资产层加"启用序号必须全量标注、单字连续在前"的前置断言，并全仓 grep 所有 `sorted(-频率)` 逐个表态。
4. **静默失败是本轮最大的类别**：正则 miss 当 0（G5）、缺 key 用默认值（G1、P12）、元素不在模板静默跳过（P6）、字典 key 覆盖（G6、G8、P3）。建议立一条工程规范：审计/生成脚本禁止 `dict.get(k, 默认)` 兜口径关键参数，解析失败必须 raise。

## 1. libchai diff（审计者：Claude 本人，逐行）

### C1【HIGH】增量路径漏"仅简码变化"的字 → 字词交叉目标漂移
- 文件：`repos/libchai/src/encoders/default.rs:362-378`（变化词采集）＋ `src/objectives/default.rs`（交叉缓存增量段，diff 行 219-262）
- 现象：`最近变化词` 在 `输出全码` 之后、`输出简码` 之前采集，只收 `全码.有变化` 的词。交叉缓存的增量刷新只遍历这个列表。但简码分配依赖 `全码空间/简码空间` 的占用竞争（default.rs:280 `序号 = 全码空间.查找数量 + 简码空间.查找数量`）：根移动改变 Y 的全码 ⇒ 前缀占用变化 ⇒ **X 的简码易主而 X 的全码不变**。X 不在变化词表，`short.实际编码 == full.实际编码` 的翻转被跳过，X 该进/出交叉统计的状态更新丢失。
- 已排除的误报可能：`输出全码` 第二段占用循环对全体词调用 `更新`，全码候选位变化会正确进表；简码兜底"无简码则简码=全码"（default.rs:293-298）保证口径成立；常规计数桶缓存遍历全体词、自行消费 `有变化` 标志，不受影响——**只有交叉缓存受害**。
- 可触发输入：hard/soft 目标区内的字 X 在某步因竞争者移动获得（或失去）真实简码。
- 预期影响：退火期间 soft/hard 单调漂移，直到下一次全量重算归正；优化器长期优化偏移目标。这是 SA 收尾"增量最优指标与完整重算不一致"警告的一个确定来源。
- 建议回归测试：构造 3 字最小资产（X、Y、词 W 占 X 全码位；X 的简码位与 Y 的全码前缀竞争），移动 Y 的根使 X 简码翻转，断言增量 soft/hard == 全量重算 soft/hard（当前会失败）。
