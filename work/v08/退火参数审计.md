# 夜莺 0.8 退火参数审计

> 状态：只审计、修测试，不启动正式退火。
>
> 原则：每个指标必须依次通过“配置可解析 → 实现口径正确 → 极小样例方向正确 → 完整基线可复算”四道门。

## 一、0.8 已确定目标

- 音码固定为小鹤双拼，不设飞键；退火只能调整型码。
- 字根、拆分、字架和读音资产继承；布局相关无理码、简码裁决、字词让位不继承。
- 一简名单固定；二简、三简在新布局上重新竞争。
- 简码手感优先于全码手感。
- 三码覆盖率继续提高；全码重码权重可以降低，但保留可用性底线。
- 允许少量同字多种型码，但不能靠它掩盖主布局问题。

### 外部评审形成的优先级假设（待实验确认）

简单鹤作者建议，在不设多重简码的前提下首先看三码率，其次兼顾手感，再尽可能避免字词撞码；同时指出三者在chai中的实际选择力可能没有想象中悬殊，最终候选常会趋近。原始证据与工程解读见 `reviews/2026-08-27_简单鹤作者/评审记录.md`。

本轮暂按“三码覆盖 → 简码手感 → 字词撞码 → 全码指标”的顺序设计对照，但不提前把它写死成权重。先用多起点短跑测量各项权重对候选分布的真实敏感度。

## 三、源码口径核验

### 1. 组合当量

已确认：`pair_equivalence` 遍历实际编码的全部相邻键，并按对象频率加权。

以 `保 bcz` 为例，简码当量包含：

- `b→c`：小鹤音码内部，布局无法改变；
- `c→z`：音末到首型，布局可以改变，也是本轮真正关心的部分。

因此原指标的优化方向并非错误，但固定音码键对会稀释数值。0.8 应增加一个单独的“音末→首型当量”，使 `bcz / bcs / bck / bcj / bcu` 的差异直接进入目标和报告。

### 2. 全码组合当量

`abxy` 会统计 `a→b`、`b→x`、`x→y`。其中只有后两项可由布局改变。0.8 中应降低整项权重，必要时拆成：

- 音末→首型；
- 首型→末型。

### 3. 分层 fingering 的疑点

已确认当前实现：

- 全局 fingering：按对象频率加权；
- 分层 fingering：只按每个字出现一次计数，没有乘字频。

这不符合“越常用的字越应当舒服”的设计意图。正式跑前必须修正或另建明确命名的字频加权分层指标，并用极小样例证明高频字的移动影响更大。

### 4. 分层是累计层，不是互斥区间

源码判断为 `index < top`，所以 `top: 300 / 500 / 1500` 分别表示前300、前500、前1500，彼此累计；不是 1–300、301–500、501–1500 三个互斥区间。

这本身可以用于优化，但报告专家所说的三个区间时，必须另外做差分统计，不能把累计层数值直接当成区间值。

### 5. 三码奖励

`levels: length: 3, frequency: 负数` 的实现是：三码对象越多，损失越低。分层计数目前按字数而非字频，这与“三码字数量”目标一致；若还要优化“三码字频覆盖率”，必须另设一项，不能混称。

### 6. 简码竞争顺序

普通简码按编码对象排序依次占位；若资产中存在显式 `排序序号`，则按该序号而非频率排序。需要专项验证：

- 固定一简是否永远先占位；
- 去掉一简后，二简是否由预期字顶上；
- 多音字的不同读音是否会错误共享排序优势；
- 冷门读音是否会偷走热门读音的简码位；
- 同字多码是否被重复计入三码数量或重码惩罚。

### 7. 字词碰撞旧修复

源码已有“初次整体验算必须重建交叉缓存”的修复，避免未移动字永久漏计。0.8 仍需做全量计算与增量移动结果一致性测试，防止同类缓存错误复发。

## 四、正式退火前的硬门槛

- [ ] 配置解析：所有启用参数均出现在最终运行配置，而非只写在生成脚本里。
- [ ] 音码冻结：任意布局下，每个读音前两码恒定；`shei/谁` 等特殊资产按既定口径处理。
- [ ] 一简固定：名单、候选位及多音读法逐项一致。
- [ ] 二简重算：一简移除后占位顺序正确。
- [ ] 三简重算：统计三码“字数”和“字频覆盖率”两种口径。
- [ ] 多音字：每个读音均参与约束，冷门读音不能代替常用读音交差。
- [ ] 全码重与简码重：分别用手工构造样例验证。
- [ ] 分层边界：300、500、1500、1674、3527、6000 的索引无 off-by-one。
- [ ] 手感：`bcz/bcs` 的损失必须高于 `bck/bcj/bcu` 中较舒服者，且差值来自 `c→型码`。
- [ ] 分层手感：高频对象的同一坏键对惩罚显著高于低频对象。
- [ ] 缓存一致性：全量重算与连续单根移动后的增量结果完全一致。
- [ ] 候选安排：所有 `score`、限键、同键绑定和可选 `null` 均列出并确认。
- [ ] 旧资产隔离：v0.7 字词让位、布局无理码、简码冻结表未渗入 v0.8。
- [ ] 报告口径：累计层与互斥区间分开输出。

## 五、参数敲定顺序

1. 简码生成与多音字正确性（先修 bug，不能靠调权重补救）。
2. 三码目标：字数、字频覆盖率及分层。
3. 简码手感：音末→首型、指法、小指和键位热度。
4. 简码重码：普通重、候选深度及平方惩罚。
5. 全码重码：降低权重但设底线。
6. 全码手感：仅作较弱的整体约束。
7. 键位分布与安排正则：压低 z/x，合理启用 f/h，防止局部极端布局。
8. 字词碰撞与五码辅助：最后作为兼顾项加入，不得反客为主。
9. 温度、步数、多起点数量：目标函数稳定后再校准。

## 六、参数选择力检查

每次改变主目标权重时，至少保留相同起点/种子的对照，并报告：

- 三码字数与三码字频覆盖率的变化；
- 前300、301–500、501–1500互斥区间的简码当量变化；
- 音末→首型当量、z/x负担、f/h利用率；
- 简码重、全码重和字词撞码变化；
- 根键排列差异数。

如果大幅改变权重却只产生统计噪声级差异，应记录“该参数在当前搜索空间选择力弱”，不继续无止境细调。

## 七、移动算子配置核验（2026-08-27）

审计发现，原实现虽然声明并展示 `random_move / random_swap / random_full_key_swap`，
但后端始终只执行单元素随机移动，配置未被消费。该问题已按
`tests/BUG-0010_退火移动方式配置未生效.md` 修复并增加防复发测试。

后续参数实验必须至少保留两组：

- 历史邻域对照：`1.00 / 0.00 / 0.00`；
- 新默认邻域：`0.90 / 0.09 / 0.01`。

在没有完成对照前，不预设交换算子一定更优；以同目标、同起点、多次重复的
分数、三码覆盖、简码手感和根键差异共同判断。
