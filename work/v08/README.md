# 夜莺 0.8：字根布局重排

> 工程记录、实验复现和发布门禁统一遵循 `../../工程规范.md`。本轮续接状态见 `项目日志.md`，问题见 `问题台账.yaml`，决定见 `决策记录.yaml`。

夜莺 0.8 不重新选根，也不推翻人工拆分；本轮只重排字根键位，并重新计算所有依赖旧键位的后处理资产。

## 继承白名单

- `根集.yaml`：全部主根、附属根与锚定关系。
- `拆分规则.yaml` 中的部件拆分、字架和结构性整字序列覆写。
- 结构性硬重码例外：`骂=[口,口]`、`侯=[亻,竖]`。这两项换键无法解除。
- 读音别名及频率修正：嗯、谁、噢等。
- 人工一简名单。
- 小鹤双拼音码、字频资产和目标词库。

## 不继承，必须重算

- 为 0.7 键位产生的顺取／按笔画无理码：媚、椅、怡、匕、箭、裔。
- 0.7 的二简、三码所有权与全部简码谕旨。
- 全码候选让位、词位占位、三码补偿和自然容错码。
- `字词冲突裁决.yaml` 中的人工裁决及自动让位结果。
- 0.7 的简码冻结基线。

上述资产只随 0.7 封存，不得进入 0.8 的布局搜索目标。新布局定稿后，从零重跑单字重码和字词撞车审计，再决定是否确有必要新增例外。

## 0.8 首轮目标

1. 重码性能不得明显劣于 0.7 基准，但不再以单一总分决定布局。
2. 分层加权键均当量应尽量单调：前 1–300 最优，301–500 次之，501–1500 再次。
3. 第一轮参考目标：`1.32 → 1.34 → 1.35`，作为比较方向而非未经验证的硬等式。
4. 单独统计第三、第四色码的按键热度，排除固定双拼音码造成的不可调负担。
5. 降低 `z/x` 的形码负担，适度利用 `f/h` 等中部好按键，同时维持现有边缘键控制。
6. 采用多起点小批量抽卡；每轮先比较少量候选，再决定参数方向和是否长跑。

## 已确认的产品原则

### 音码不飞键

- 所有正式编码的前两键严格使用小鹤双拼。
- 不允许为了手感把某个音节迁移到另一音码，例如把 `xq` 攀到 `xo`。
- 多音字仍可按真实读音登记多个入口，但不得创造不存在的读音位置。

### 允许少量多重形码

- 不强求每个字永远只有一个可输入编码。
- 正式主码必须规则明确；个别字可在确有直觉或实用价值时增加备用形码。
- 多重编码不得成为掩盖主体布局缺陷或虚增跑分的手段，必须单独登记。

### 简码覆盖与简码手感优先

- 一简、二简、三码全部参与手感评价，且简码手感高于全码手感。
- 降低全码手感和全码重码在总目标中的权重；全码仍须维持可用底线，但不再主导布局。
- 提高三码覆盖目标。当前夜莺前 6000 字约有 3300 个三码字，简单鹤约 3690 个；约 390 字的差距不能用十余个多重一简解释，应作为 0.8 的核心优化方向。
- 三码数量必须与三码手感联合评价：不能仅把更多字塞进三码，却集中到难按键或制造明显候选压力。

## 版本隔离

- `releases/v0.7` 是当前可用基准，不由 0.8 实验覆盖。
- 0.8 是夜莺主工程的正式新版本；配置、运行结果和报告全部写入主仓 `work/v08/`。
- `夜莺B/` 只作为已经完成的选根阶段和上游字根/拆分资产来源，不再承载0.8版本身份。
- 未经人工选定的抽卡候选不得写入正式发布目录。
