# BUG-0006：同字同音码频率聚合验证

日期：2026-08-27

状态：已验证。

## 契约

`readings.json` 的每条记录是 `[频率, 编码]`。对简码竞争而言，完整编码的前两位才是双拼音码，因此：

- 同一个字、同一个双拼音码的多条记录，频率必须求和。
- 同一个字的不同双拼音码分别统计。
- 行顺序不得改变结果。
- 畸形记录必须失败，禁止静默默认或覆盖。

该契约集中实现在 `夜莺B/scripts/reading_frequencies.py`，不再允许各审计脚本自行用字典推导式或 `max` 定义另一套口径。

## 修复范围

- `global_collision_audit.py`：移除 last-wins。
- `candidate_root_check.py`：移除同源 last-wins。
- `polyphone_slot_audit.py`：移除独立的 max 口径。

`rows[0]` 是否为主读音属于 P4/读音排序契约，不在本 Bug 中冒充已解决。

## 回归测试

```text
python -m unittest -v tests.test_reading_frequencies
```

结果：5/5 通过，覆盖求和、音码隔离、顺序不变和两类坏输入。

真实数据抽查：

- `教/jn`：1,205,433 + 1,205,433 = 2,410,866；旧 last-wins 仅保留 1,205,433。
- `传/ir`：918,357；`传/vr`：48,335，两个音码没有互相混合。
- `嗯/ng`：0；`嗯/en`：157,982，仍如实暴露主读音顺序问题，留给后续排序契约处理。

两个正式审计脚本均可在完整数据上运行完成：全局审计得到三码落选650字音/649字、全码重码125对/227字；多音审计得到二简变化54、三码变化250。
