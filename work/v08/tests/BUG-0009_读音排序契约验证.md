# BUG-0009：读音排序与别名重建契约

日期：2026-08-27

状态：已验证。

## 发现

旧 `work/readings.json` 有23个字未按频率降序。典型的“嗯”为 `ng=0` 在前、`en=157982` 在后，任何直接读取 `rows[0]` 的脚本都会把它当作零频字。

## 契约与实现

- 每字读音列表按频率稳定降序；首条才允许定义为主读音。
- `load_readings` 加载时强制断言，乱序资产失败，不再静默消费。
- `primary_readings` 是主频和主码的统一入口。
- `apply_reading_aliases.py` 改为显式 `--input + --rules → --output`，禁止输入输出同路径。
- 别名频率必须显式提供；字有多个形码后缀时，规则必须显式提供 `suffix`。
- 生成0.8规范资产 `work/v08/assets/readings.json`；保留历史 `work/readings.json` 不动。

三个当前多音审计消费者已迁移到0.8规范资产和统一加载器。

## 验证

- 读音契约测试9/9通过。
- 全部相关回归合计20/20通过。
- 0.8规范资产共8105字，通过全量排序断言；“嗯”的主记录为 `[157982, "enar"]`。
- 全局三码/全码审计与多音简码审计均可完整运行，结果与BUG-0006修复后的正确聚合口径一致。

历史目录中仍有若干脚本直接读取旧资产并使用 `rows[0]`；它们不属于0.8生产链，代码目录中继续按历史工具管理，不得被新流程调用。
