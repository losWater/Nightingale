# BUG-0010：退火移动方式配置未生效

## 状态

已修复，2026-08-27。

## 现象

Chai 配置和图形界面提供三项移动权重：

- `random_move`：随机移动一个元素；
- `random_swap`：随机交换两个元素；
- `random_full_key_swap`：随机交换两个整键。

界面默认显示为 `0.90 / 0.09 / 0.01`，但优化入口没有把 `search_method`
传给操作器，操作器也始终直接调用“随机移动元素”。因此无论如何修改界面或
YAML，实际搜索都等价于 `1.00 / 0.00 / 0.00`。

## 产生原因

`变异配置`、默认值和前端表单已经建立，但后端的两个交换算子未实现，配置也
没有接入操作器构造和变异分派。这是一个“配置结构先建立、执行链未完成”的
半实现功能。

## 影响

- 历史退火结果并非口径错误；所有历史链实际都使用单元素随机移动。
- 历史配置中写入的移动比例不能作为实验变量解释。
- 搜索邻域过于单一，可能提高陷入局部最优的概率。

## 修复

- 操作器读取并校验三项非负有限权重，按相对权重抽样，不要求总和恰好为 1。
- 实现“交换两个合法元素”，提交前验证双方安排和条件。
- 实现“整键交换”，同时替换所有直接键位安排中的两个编码键；归并和未选取
  安排保持不变，提交前验证全部受影响元素。
- 命令行、Web 与 Server 三个优化入口全部传入 `search_method`。
- 保留原 `默认操作::新建` API；未显式配置时使用 `0.90 / 0.09 / 0.01`。

## 防复发测试

`src/operators/default.rs` 中新增测试覆盖：

- 合法双元素交换；
- 单键和多键安排的整键交换；
- 归并及未选取不受整键交换影响；
- 设置为 100% 随机交换时，变异分派确实走交换路径。

GNU 工具链验证：`cargo test --lib` 与 `cargo check --all-targets` 均通过。

## 后续实验口径

旧版对照必须显式配置 `1 / 0 / 0`；新版默认邻域配置为 `0.90 / 0.09 / 0.01`。
两者不可混称为同一种退火参数。
