# BUG-0005：前沿汇总失败即停验证

## 原问题

`analyze_frontier_results.py` 的任一正则未命中时返回 `None`，调用方直接 `continue`。metric格式变化、profile目录错误或线程缺失都会让候选悄悄消失，最终仍可能生成看似正常的Pareto集合。

## 修复

- metric解析缺少“一字全码／一字简码／字词交叉”任一段时，报告具体段名与文件并终止。
- profile名单和预期线程数改从 `manifest.json` 读取，不再硬编码三个名称。
- 缺manifest、缺profile、output目录不是恰好一个、线程名非法、线程缺失或多余均失败。
- 没有候选满足硬门槛时拒绝输出空Pareto结论。
- 当前文本解析器仍服务历史指标格式；0.8格式变化会明确阻断，不能被误当作已支持新层级。

## 验证

7项专项测试通过，包括故意破坏metric段名、缺manifest/profile/thread、多output目录、零有效候选和自定义profile正例。

真实历史suite `tiered_hard_3profiles_12x100000_20260825_021530` 严格复算通过：3 profile × 12线程共36项全部齐全，15项满足硬门槛，12项进入Pareto。

与简码所有权、字词交叉、多音频率、读音排序和手感指标合并回归共39项，全部通过。
