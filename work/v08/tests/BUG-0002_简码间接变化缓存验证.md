# BUG-0002：仅简码变化的增量缓存验证

日期：2026-08-27

状态：已验证。

## 根因

旧 `默认编码器::编码` 在 `输出全码` 后、`输出简码` 前冻结 `最近变化词`，且只收集 `全码.有变化`。竞争者移动可能改变另一个字的简码归属，而该字全码完全不变；字词交叉缓存只遍历冻结集合，因而漏掉该字进入或退出“简码实际编码等于全码”的状态变化。

## 修复

- 简码存在时先完整执行 `输出简码`。
- 之后统一收集 `全码.有变化 || 简码.有变化` 的对象。
- 非纯移动路径仍返回 `None`，保持全量刷新语义。
- 抽出 `收集实际编码变化词`，避免以后再次把采集条件散落进编码流程。

## 回归

三字 Rust 夹具分别设置：仅全码变化、仅简码变化、均不变化。变化集合必须精确为前两个字；旧逻辑会漏掉第二个字。

```text
rustup run stable-x86_64-pc-windows-gnu cargo test --lib
```

结果：Rust 2/2 通过，其中 BUG-0002 专项测试通过。

随后重新构建 release 引擎，并运行跨语言字词交叉完整资产测试：Rust 引擎与独立 Python 审计器仍精确一致；相关 Python 回归20/20通过。

该测试直接封住导致缓存漏刷的变化集合入口；正式退火仍须保留收尾全量重算和独立复算双门禁。
