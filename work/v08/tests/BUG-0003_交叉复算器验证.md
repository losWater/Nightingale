# BUG-0003：字词交叉独立复算器验证

日期：2026-08-27

状态：已验证，可恢复为正式门禁。

## 已修正语义

- 按 libchai 的内部词表顺序计算字频层级；显式 `排序序号` 优先，否则按频率稳定降序。
- 全码按首选生成实际编码，简码保留自身候选位，再比较二者的实际编码。
- 支持目标自身 `hard_character_top`；未覆盖时仅对 `hard: true` 目标回退全局阈值。
- `character_tiers.top` 使用与 Rust 相同的零基下标 `< top` 口径。
- 配置、码表列数、元素对齐、排序标注和单字连续区间均改为失败即停。
- 历史产物可用显式 `--config` 指向不在 output 目录内的配置，禁止猜路径。

## 自动测试

命令：

```text
python -m unittest -v tests.test_audit_cross_collision
```

结果：10/10 通过。覆盖全局阈值、目标阈值、排序、真实短码、无简码回退、显式四键次选短码，以及四类坏输入拒绝。

修复前的有效红灯基线为 1/5 通过；排序、全局阈值、真实短码和四键次选短码四项失败。

## 真实资产检查

- 0.7 最终发布构建可完整读取，独立复算结果为：硬碰撞 2，软碰撞 18.3725。
- 该历史 `metric.txt` 没有打印字词交叉项，因此只能作为冒烟检查，不能作为逐项相等证据。
- 另一份历史运行的引擎记录为 0 / 83.2350，按当前修复后 Rust 语义复算与其不一致。
- 该运行产生于交叉缓存全量刷新缺陷修复之前，历史指标可能正是 BUG-0002 的受污染结果；必须由当前 Rust 引擎重新编码同一夹具后再裁决。
- 当前直接重放历史 solution 配置会因缺失生成映射空间而报“元素无法在键盘映射中找到”，不能把旧产物直接冒充当前引擎基准。

## 当前引擎黄金对账

集成测试 `tests.test_cross_collision_engine_parity` 使用同一份当前配置和元素表，先调用当前 release Rust 引擎重新编码，再由 Python 从引擎生成的 `code.txt` 独立复算。

- Rust：硬碰撞 18，软碰撞 40.5125。
- Python：硬碰撞 18，软碰撞 40.5125。
- 结果：逐项精确一致。

总回归命令：

```text
python -m unittest -v tests.test_audit_cross_collision tests.test_cross_collision_engine_parity
```

结果：11/11 通过。

## 退出条件

已满足：当前 libchai 与独立 Python 审计器在真实完整资产上逐项相等。后续任一侧改变交叉碰撞语义，均必须同步通过跨语言集成测试。
