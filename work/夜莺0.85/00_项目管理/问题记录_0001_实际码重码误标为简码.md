# 问题记录0001：实际码重码误标为简码

- 发现时间：2026-08-29 18:38 +10:00
- 涉及脚本：`scripts/audit_candidate_collisions.py`
- 现象：报告把按 `actual` 字段分组得到的全部重码称为“简码重码”，其中实际包含四码重码。
- 原因：统计逻辑没有限定 `actual` 的长度小于4，但展示标题误用了“简码”。
- 影响：容易把同一批四码冲突误认为全码冲突之外的另一批简码冲突，造成重复审查。
- 修复：报告统一改称“实际码重码（可能是简码或四码）”。底层 JSON 字段名暂时保留，以免破坏既有读取程序。
- 防复发：以后指标名称必须与筛选条件逐项核对；若确需“仅简码重码”，必须显式限制码长小于4。
