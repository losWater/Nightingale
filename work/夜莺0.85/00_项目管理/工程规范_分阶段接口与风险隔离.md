# 工程规范：分阶段接口与风险隔离

## 核心原则

工程按 `A＋B＝C，C＋D＝E，E＋F＝G` 分阶段构建。处理任一阶段时，只允许消费已经验收的上游接口和本阶段显式输入；禁止绕过接口回读更早中间产物并重新猜测语义。

## 当前映射

- A：G8C12原始退火结果、8454字音身份与基础拆分；
- B：人工单字码位裁决、无理码及路径层级声明；
- C：冻结的正式单字接口包；
- D：冻结的基础词库与词码；
- E：身份级无简词综合字词审查表；
- F：人工字词让位／候选裁决；
- G：最终综合字词码表。

## 接口要求

C不能只有两列普通码表，至少必须包含或引用：

1. 最终单字码表；
2. 字音身份审计；
3. 人工路径层级表；
4. 裁决和无理码清单；
5. 输入输出哈希及门禁报告。

E只能由冻结C与冻结D生成。F只能作用于验收后的E。若E有问题，先判断是C接口错误、D错误还是`C＋D`实现错误；不得在F中偷偷补偿。

## 变更规则

- 上游接口内容发生变化时，必须发布新的接口版本并重新生成全部下游产物；
- 旧下游产物标记过期／勿用，不覆盖历史证据；
- 每阶段输出目录必须不存在，拒绝覆盖；
- 每阶段必须反读输出并核验候选顺序、条目守恒、来源覆盖与哈希；
- 下游不得依据字形等启发式规则反推上游丢失的读音身份或路径层级。
