# 脚本设计 0022：按读音字频数据源审计

## 状态

- 设计时间：2026-08-28（Australia/Sydney）
- 状态：数据源审计中，尚未修改当前字音频率表

## 目标

建立以 `(汉字, 实际普通话读音)` 为统计单位的频率表。多音字的不同读音必须拥有各自的权重；不得把整字总频率复制给每个读音，也不得在分配权重前按字形去重。

例如，`行/xing` 与 `行/hang` 是两个独立退火元素。最终编码可以去掉声调，但来源统计应尽可能保留带调读音，以免过早合并不同音项。

## 数据源候选与判定

### 1. Chai `dictionary.txt`

- 优点：完整覆盖当前 8105，能生成 8454 个去调字音项。
- 风险：上游语料与统计口径尚未证实；存在 336 个零频项。
- 结论：保留为读音覆盖候选和当前临时基线，不直接视为可信的分读音自然字频。

### 2. Tsai `character-syllable.txt`

- 来源为 libtabe 0.1.3 词典的 111,417 个有效词条。
- 统计的是某读音出现于多少个不同词条的类型频率；明确没有使用词条实际频率。
- 结论：适合辅助判断读音覆盖与大致主次，不等于自然文本中的 token 字频，不可独立作为最终权重。

### 3. CVTE-Poly 等多音字消歧训练／测试集

- 数据为模型训练与评测而构造；CVTE-Poly 明确强调数据更平衡。
- 结论：适合训练或验证注音器，不适合直接统计自然读音占比。

### 4. SUBTLEX-CH 词频＋逐词拼音

- 词频来自影视字幕自然语料；公开说明中的词频规模约为 3350 万词。
- 整合词频／词性文件包含词形总频率与拼音字段。
- 候选算法：逐词核验“汉字数＝拼音音节数”，将该词的 token 频次累加到每个对齐的 `(字, 带调读音)` 项。
- 风险：拼音字段可能只给词条规范读音；分词错误、儿化、异读、非汉字符号及单字词多音判定均需单独审计。
- 结论：当前最值得实测的公开、可追溯候选；必须先做原始文件结构与覆盖审计。

## 拟实现功能

先实现只读审计器，不直接生成权威频率表：

1. 固定下载地址、下载时间、许可证／引用说明与 SHA-256。
2. 检测压缩包内文件、字符编码、列名、行数及频率总量。
3. 检测词形与拼音能否逐字／逐音节对齐。
4. 统计可对齐词频占全部词频的比例。
5. 仅对当前 8105 和当前 8454 字音候选做覆盖比较。
6. 列出多音字的候选分布，并重点抽查 `行、重、长、都、得、地、着、还、咯、哼、谁` 等字。
7. 所有无法对齐、读音不在当前候选集、零频及来源冲突均单独输出，不静默修正。
