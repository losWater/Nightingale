# 夜莺重开工程：基线与脚本规范

## 1. 当前数据架构

夜莺的单字退火数据分为四层，各层不得混用。

1. **根集**
   - 定义字根、部件归并、附属关系和键位锚定关系。
   - 当前参考资产：`夜莺B/work/根集.yaml`。

2. **人工规范拆分规则**
   - 只定义部件或汉字在结构上应当如何由字根组成。
   - 不得包含无理码、容错码、副码、简码谕旨、候选顺序、字词让位等编码层规则。
   - 当前参考资产：`夜莺B/work/拆分规则.yaml`；该旧文件存在跨层混装，不可整份直接继承。

3. **8105 字最终规范拆分表**
   - 统计单位是唯一字形，每字一行。
   - 记录完整规范拆分、编码首根和编码末根；不记录读音与频率。
   - 根集与人工规范拆分规则经 Chai 分析后得到该表。

4. **8455 条退火元素表**
   - 统计单位是“字形＋读音”，不对多音字去重。
   - 每条记录：汉字、读音元素、形码首末根、该读音的独立频率。
   - 它由 8105 字规范拆分表与字音频率数据合并生成，是 Chai 退火的直接输入。

数据流：

```text
根集＋人工规范拆分规则
          ↓
   8105字规范拆分表
          ↓ 加入分读音频率
   8455条退火元素表
          ↓
        Chai退火
```

## 2. 重开规则

- 之前存在的脚本一律视为**不存在的历史参考**，不默认其可用、正确或具有权威性。
- 旧脚本不得直接用于新流程；即使功能看似相同，也必须先按新口径重新定义。
- 任何新功能需要脚本时，必须先在文档中记录：
  1. 脚本名称与路径；
  2. 要解决的唯一问题；
  3. 权威输入及其口径；
  4. 预期输出及其口径；
  5. 不得修改的内容；
  6. 必须通过的验收与失败条件。
- 上述设计记录完成并经确认后，才现场重新编写脚本。
- 不使用临时脚本修改任何权威资产。
- 每次运行必须明确输入、输出和时间，不得静默覆盖上游资产。
- 每次结构资产修改并重新生成8105表后，必须按
  `00_项目管理/同拆字检查规范.md`执行同拆字检查；同拆字、同首末骨架和最终重码
  三个概念不得混用。

## 3. 进度记录规则

- 进度表使用 Australia/Sydney 时区（UTC+10:00，应随当地夏令时变化）。
- 每条记录精确到分钟，并显式保存 UTC 偏移。
- 每条至少包含：当前进度、已经拥有的资产、下一步、尚需要的信息或资产。
- 进度表按时间追加，不覆盖旧记录。
