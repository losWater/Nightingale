# 脚本设计0064：十六轮无人值守三十二强

## 目标与数量

总计按16轮计数：设计0054旧卡池作为第1轮，既有C11、C07占据该轮两个出线名额；
再运行15轮新卡池，每轮16张互异随机起点、每张200000步，每轮取前2张。最终恰为
`2+15×2=32`张，不额外扩成34张。

## 无人值守前提

形码盒子TypeScript脚本不得继续通过`vite-node`现场编译，因为Vite会创建编译辅助子进程，
触发沙箱逐命令授权，无法无人值守。正式流程先用esbuild将赛码入口及依赖捆绑为固定的
Node.js ESM文件，再直接由Node运行。必须用已完成的第一轮复算，并与原始TS执行结果的
逐段指标、综合得分、bootstrap计数和来源哈希完全一致，才允许接入批处理。

## 种子与继承关系

- 新增第1—4轮沿用已完整退火的830001、840001、850001、860001卡池；
- 新增第5—15轮使用870001、880001、……、970001起始的连续16种子；
- 全部继承0054母配置、元素表、Chai二进制、按键分布和当量表；
- 不修改根集、拆分、读音频率、简码、退火参数或赛码权重。

## 单轮状态机

每轮依次执行并落盘状态：建卡 → 退火 → 封存哈希 → 核心指标 → 附加手感 → Pareto →
16张普通单字表 → 79段书面/LCCC赛码 → 硬门禁 → 选出前2。已完成且哈希/门禁通过的
步骤直接复用；半成品隔离，不得凭文件存在静默跳过。

单轮出线以分段稳定性均衡得分为主，必须先满足前300有效全码重为0、表身份完整、缺字
集合逐段一致。报告同时列出四套权重、bootstrap、三码、重码、传统手感、热力和三项附加
指标；若第二名与第一名布局重复或硬门禁失败，则顺延，不改变指标权重。

## 长任务与恢复

正式编排器是仓库内可审计脚本，不使用临时脚本。它输出JSON状态清单、逐轮日志和分钟级
进度；进程可持续数小时。外层代理通过长等待会话守候，阶段完成后自动衔接。若会话意外
终止，重新运行同一命令必须从首个未完成状态恢复，不重跑已封存的成功退火。

## 终局

新增30张晋级卡与旧C11、C07统一生成32强身份映射，进行同语料、同79分段、同四权重和
bootstrap总赛，最后执行既定否决项审计。
