# 脚本设计 0002：生成 8105 规范拆分表

## 状态

- 设计时间：2026-08-27 22:42 +10:00
- 状态：用户已确认，实施中
- 预定脚本：`work/重开工程/scripts/build_canonical_8105.py`

## 要解决的唯一问题

用当前根集和当前待验收人工结构拆分，通过 Chai 原生分析重新生成纯结构层的
8105 字规范拆分表，替换已经混入整字覆写、无理码和编码裁决的迁移旧表。

## 权威输入

1. `01_根集/根集_待完整性复核.yaml`。
2. `02_规范拆分/人工规范拆分_待验收.yaml`。
2a. `02_规范拆分/传播式整字结构覆写_待验收.yaml`：仅用于Chai无法表达的唯一
    结构规范，禁止编码层规则。
3. 旧 8105 表的“汉字”列：只用于确定恰好 8105 个字形，不继承任何拆分结果。
4. `04_Chai输入/结构分析基线_待审计.yaml`：仅继承 Chai 字库、字形定制、
   变换器、分类器、退化器和选择器；根映射和人工拆分必须现场重建。
5. 固定版本的 `repos/webchai/packages/hanzi-chai`，包括已记录的本地 diff 指纹。

## 生成规则

- 应用 `component_splits`，随后应用已声明原序列和规范序列的传播式结构覆写。
- 不读取或应用历史 `sequence_overrides`、`frames`、无理码、容错码、简码谕旨、
  候选顺序或字词让位。
- 完整拆分列保留具体根形名称；编码首末根才按附属关系归并宿主根。
- 锚定根保留自身根名，只共享键位，不归并名称。
- 当前待验收规则中的已知待修复项（`我`、`虭`）不得由脚本暗中修正。

## 预期输出

1. `02_规范拆分/最终规范拆分表_待核验.tsv`：UTF-8 BOM，8105 行。
2. `02_规范拆分/最终规范拆分表_待核验.html`：UTF-8 人工阅读版。
3. `02_规范拆分/最终规范拆分表_生成清单.json`：输入哈希、引擎指纹、运行目录、
   生成时间和验收计数。
4. 被替换的现行表移动到 `99_历史参考/历次8105表_<时间>/`，保留可恢复副本。
   首次运行前已经确认受污染的迁移旧表仍使用明确名称
   `被编码层污染的旧8105表_<时间>`。

## 不得修改

- 根集。
- 人工规范拆分规则。
- 人工规则待修复表与拆分待修复表。
- hanzi-chai 源码及字形数据。
- 任何历史文件内容；旧表只允许原样迁移归档。

## 必须通过的验收

1. 输入和输出均为 8105 个不重复单字字形，字集精确相等。
2. 每个字必须有非空完整拆分。
3. 每个完整拆分元素必须能显示为确定名称。
4. 编码首根和末根必须能由完整拆分及当前根集唯一推导。
5. TSV 与 HTML 行数一致。
6. 所有验收通过前不得替换旧表；替换时必须先将旧表归档。
7. 保存所有输入 SHA-256、脚本 SHA-256、引擎提交、dirty 状态和 diff SHA-256。
