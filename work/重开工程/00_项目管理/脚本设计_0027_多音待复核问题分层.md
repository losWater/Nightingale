# 脚本设计 0027：多音待复核问题分层

## 目标

将设计 0026 留下的 405 个待复核单字按问题性质分层，区分读音覆盖问题、来源覆盖不足、主读音冲突和样本不足，避免将所有“集合不一致”误称为当前 8454 漏音。

## 实施结果

- 状态：已实现。
- 待复核 405 项、频率 1,652,894。
- 来源提示当前可能漏音 187 项、涉及频率 1,174,720；该集合只是查证队列，不是批量补音决定。
- 当前含 Unihan 未列读音 277 项，说明旧频率表覆盖不足是集合不一致的主要来源之一，不能反向删除当前读音。
- Unihan 未覆盖 151 项、小样本 118 项、主读音冲突 32 项。
- 已完成最高影响候选的第一批人工核验，结论另见 `高影响可能漏音核验_第一批.md`。

## 集合口径

- `S`：SUBTLEX 单字词条列出的去调读音集合。
- `C`：当前 8454 的去调读音集合。
- `U`：Unihan `kHanyuPinlu` 的去调读音集合。

## 分类字段

- `来源提示当前可能漏音 = (S ∪ U) - C`
- `当前已有但SUBTLEX未列 = C - S`
- `当前已有但Unihan未列 = C - U`
- Unihan／Chai 主读音是否冲突。
- Unihan 是否未覆盖、是否低于 100 样本。

这些字段只描述集合关系，不自动判断某读音应增、应删。旧读音、方言读音、语气词变体及审音变化必须另查现代规范来源。

## 输出

- `多音待复核问题分层.tsv`
- `多音待复核问题分层.md/json`
- `当前8454可能漏音候选.tsv`

## 边界

- 不修改读音集合或频率。
- 不把来源未收视为当前多收。
- 不把来源收录自动视为现代普通话有效读音。
