# 脚本设计 0038：新输入退火冒烟配置与运行

## 目的

在不修改设计0035—0037已验收输入的前提下，用 Chai 原生 `encode` 和
`optimize` 完成一次低成本端到端冒烟。它只验证“新8454输入 → 指标 → 退火 →
结果 → 再测量”整条链可运行，不用于选定正式布局或最终权重。

## 输入

- `04_Chai输入/夜莺0.8退火基础配置_待核验.yaml`
- `04_Chai输入/夜莺0.8退火元素表_待核验.yaml`
- 项目实际构建的 `repos/libchai/target/release/chai.exe`

源配置和元素只读；冒烟配置与全部 Chai 输出写入新的实验目录，禁止覆盖。

## 临时目标口径

- 统计层固定包含：300、500、1500、1674、3527、6000。
- 三码率是核心目标：300、500、1674、3527各给`-15`，6000给`-70`。
- 简码手感：300、500、1674层的大跨/小跨权重暂用`100/20`。
- 前300有效全码重码权重暂用`4`作保护；其余全码重码只测量，不优化。
- 全局与各层的重码字段全部保留，以便结果完整报告；零权重表示观察项，
  不是删除指标。
- 本轮不把按键热力直接写入目标函数，热力仍作为结果门禁观察。
- 基础输入不继承0.7简码所有权；冒烟配置显式启用Chai自然简码：每个单字先尝试
  二码首选，再尝试三码首选。若不启用此规则，简码指标为空并产生`NaN`。

这些数值只继承最近一次已审计冒烟的尺度，并把旧1500目标层替换为正式1674
口径、补入3527观察/三码层。是否用于正式多起点必须另行裁决。

## 退火规模

- 2条链；每链5000步。
- 混合移动：单根移动0.90、交换0.09、整键交换0.01。
- 沿用最近已验证温区：`t_max=4.455057485836668`，
  `t_min=0.0021753210380061855`。
- 冒烟不用于比较移动算子，也不据单链最好值下结论。

## 新代码

`scripts/build_v08_smoke_config.py`：从已验收基础配置纯函数式生成本轮配置；
拒绝输入输出同路径，重建目标字段和退火参数，并把源/输出哈希写入manifest。

## 验收

1. 生成配置通过项目实际 `libchai.validate`。
2. 先以同一冒烟目标运行基线 `encode`，再运行2链 `optimize`。
   基线`metric.json`任一必需数值出现`NaN/null`时禁止启动优化。
3. 每条结果必须包含`config.yaml`、`code.txt`、`metric.json`。
4. 汇报时同时给出三码、简码手感、全码/有效全码/简码重码、前1500全码重、
   300/500/1674/3527/6000分层以及按键热力；不得只报最好项。
5. 冒烟结果不得写入发布目录，也不得替换根集、拆分表、频率表或正式输入。
