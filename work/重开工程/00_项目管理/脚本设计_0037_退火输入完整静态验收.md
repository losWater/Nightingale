# 脚本设计 0037：退火输入完整静态验收

## 目标

在启动任何退火前，对设计0035生成的夜莺0.8输入做一次独立静态验收。验收脚本只读，不修改频率、元素或配置。

## 输入

- 设计0020原始8454字音表；
- 设计0036融合自然频率预览；
- 设计0035退火有效权重表、退火元素表与基础配置；
- 当前8105规范拆分；
- 特殊优化权重裁决与残余未分配清单。

## 验收项目

1. 原始、融合、有效权重、元素表的 `(汉字, 拼音)` 身份集合完全一致，均为8454项。
2. 全部覆盖当前8105字，无缺字、多字或重复身份。
3. 元素表频率逐项等于有效权重表，允许有限小数。
4. 每条元素序列恰为4，所有元素都能在配置映射中解析。
5. 特殊权重变化范围恰为裁决资产中的`谁/shei、谁/shui`。
6. 统计原始／融合／有效零频、正频转零、零频转正及频率总量。
7. 残余未分配清单项目数和频率与生成清单一致。
8. 输出相对原Chai频率变化最大的头部字音，供人工检查。
9. YAML配置、元素表能完整加载并通过基本结构断言。
10. 使用项目实际依赖的libchai WASM原生`validate`加载配置；Python YAML解析通过不能替代本项。
11. 元素表每一项的频率必须是非负整数；配置原生校验不覆盖元素反序列化，
    首次运行前还必须用 Chai 原生 `encode` 做端到端读取验收。（BUG-0006修正）

## 输出

- `04_Chai输入/夜莺0.8退火输入_静态验收.json`
- `04_Chai输入/夜莺0.8退火输入_静态验收.md`
- `04_Chai输入/夜莺0.8退火输入_频率变化头部.tsv`
- `04_Chai输入/夜莺0.8退火输入_libchai原生验收.json`

## 验收门槛

- 所有硬断言通过，报告状态方可为`pass`。
- 报告必须列出完整核心指标；不能只给“通过”。
- 连续双跑输出哈希一致。

## 原生校验脚本

`scripts/validate_chai_config_native.ts`由Bun执行，直接导入当前WebChai安装的`libchai`，对生成配置调用WASM `validate`。

## 实施结果

- 状态：全部静态验收通过，包含libchai WASM原生校验。
- 字／字音／元素：8105 / 8454 / 8454；三层身份集合完全一致。
- 元素序列全部长4、全部元素可映射、元素频率逐项等于有效权重。
- 零频（原始Chai／融合自然／最终有效）：336 / 264 / 265。
- 原正频转最终零频32项；原零频转最终正频103项。
- 原始频率总和2,522,799,818；融合自然频率总和2,521,220,566；最终有效权重总和2,519,725,655.75。
- 特殊覆盖恰为`谁/shei、谁/shui`；残余未分配仍为9项、61,287频率。
- 频率变化头部已人工抽查，`了、长、谁、地、重、着、的、什、血、都`等变化均能由分读音比例或特殊裁决解释。
- 发现并修复BUG-0005：继承基线中的`gb2312: false`经生成器规范为`gb2312: 0`后，libchai原生`validate`通过。
