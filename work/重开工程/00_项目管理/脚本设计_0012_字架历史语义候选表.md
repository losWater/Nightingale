# 脚本设计 0012：字架历史语义候选表

## 状态

- 设计时间：2026-08-28 01:02 +10:00
- 状态：已实施并完成双跑复现；仅生成候选，未覆盖权威8105

## 目的

在已经由Chai原始结构树确认的字架直接字和嵌套用户范围内，恢复旧正式表所记录的
最终字架语义，得到一份精确的迁移影响候选表。本脚本不是未来正式字架编译器。

## 输入

- 当前权威8105规范拆分表。
- 只读字架迁移审计JSON及其输入哈希。
- 旧正式`最终规范拆分表_人工阅读.tsv`，只作为历史裁决结果来源。
- 当前根集，用于验证候选序列没有引用未知根。

## 算法

1. 仅允许修改审计器已通过结构树确认的29个直接字和10个嵌套用户。
2. 当前序列与旧序列经附属归并、笔画名称归一后语义相同的字不修改；目前预期为
   斑、癍。
3. 其余字以旧正式表的字架边界为历史目标；若旧序列中的中芯不是当前根，必须通过
   当前8105规范表递归展开，无法展开或发生循环立即失败。已发现街的圭需展开为
   `土＋土`，裹的果需展开为`日＋木`。
4. 重新计算首末宿主根。
4a. 旧人工阅读表会把附属字架折叠显示为宿主。候选结构表必须反向恢复实际结构形：
    辡家写辡、编码归辛；玨家写玨、编码归王。
5. 候选表必须仍为8105个互异字，全部序列非空，所有元素属于当前根、附属根或笔画。
6. 对候选表运行结构同拆候选检查，并以当前权威表作为上一版比较。

## 输出

全部进入带时间戳的`05_退火实验/字架历史语义候选表/`目录：

- 候选8105 TSV；
- 37字预期变化明细TSV；
- 候选生成JSON清单；
- 独立的结构同拆候选JSON、TSV和Markdown。

## 安全边界

- 不修改根集、人工拆分、字架盘点资产或当前权威8105。
- 不调用旧版字架token子串传播代码。
- 候选表只用于确认历史语义和影响范围；正式迁移仍需结构树递归编译器复现候选。

## 验收

- 结构确认范围39字，语义变化37字，不多不少。
- 斑、癍不发生无意义改写。
- 旧字架目标中的每个元素均可映射到当前根集。
- 输出哈希可复现，结构同拆候选差异完整报告。
