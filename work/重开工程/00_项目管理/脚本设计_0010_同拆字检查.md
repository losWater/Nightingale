# 脚本设计 0010：同拆字检查

## 状态

- 设计时间：2026-08-28 00:38 +10:00
- 状态：已实施并接入8105正式生成流程

## 目的

每次重新生成8105规范拆分表后，自动检查结构碰撞，防止一次人工结构修正悄悄
制造新的同拆字，并保留可追溯的前后版本差异。

## 术语边界

- 同拆字：编码音节相同（不计声调）且完整规范拆分序列完全相同。
- 结构同拆候选：只确认完整拆分相同，尚未结合读音；8105阶段只能得到这一层。
- 同首末骨架：仅编码首根和编码末根相同，不称为同拆字。
- 重码：加入读音、键位和取码规则后编码相同；本脚本不检查真实重码。

## 输入

- 必需：本次生成的`最终规范拆分表_待核验.tsv`。
- 可选：生成前归档的上一版同名TSV；没有上一版时只生成当前快照，不伪造差异。
- 表格必须恰有8105个互异汉字，且拆分、首根、末根均非空。

## 输出

- `02_规范拆分/同拆字检查.json`：机器可读的完整结果、输入哈希与版本差异。
- `02_规范拆分/同拆字检查_结构候选组.tsv`：全部完整拆分相同的结构候选及成员。
- `02_规范拆分/同拆字检查_同首末骨架组.tsv`：全部至少含两个字的首末骨架组。
- `02_规范拆分/同拆字检查.md`：便于人工查看的摘要。

## 算法

1. 8105阶段按完整规范拆分字符串分组，仅保留成员数至少为2的结构候选组。
2. 按`编码首根／编码末根`分组，仅保留成员数至少为2的组。
3. 若提供上一版，按“拆分序列＋成员集合”比较同拆组，报告新增、消失和成员变化。
4. 同一输入重复运行必须产生相同的结构数据；时间只写入JSON元数据和Markdown摘要。

## 接入生成流程

- `build_canonical_8105.py`在新表落盘、旧表归档后立即调用本检查。
- 本次归档表自动作为上一版输入。
- 检查失败则整次生成失败，不得留下“生成成功但没有结构碰撞报告”的状态。
- 生成清单必须记录检查脚本及四个报告文件的哈希。

## 验收

- 当前表应报告15个结构同拆候选组，不得写成15组同拆字。
- 奭、襫、爽均不属于任何同拆组。
- 用奭修改前一版比较，变化同拆组应为0。
- 单独运行与生成流程自动运行结果的结构内容一致。
