# 脚本设计0051：恢复自然一简并重置正式抽卡

## 问题

设计0038只启用了自然二简和三码，漏掉了一简。因为一简会释放原二简码位并触发后续
身份递补，所以不能只在成品码表中追加；设计0040—0050产生的参数比较、正式抽卡与
试用表全部标记为“无一简历史结果”，不得作为0.8正式候选。

## 修复

修改唯一配置生成源`scripts/build_v08_smoke_config.py`：对单字依次启用
`prefix=1,count=1`、`prefix=2,count=1`、`prefix=3,count=1`。仍不继承0.7人工简码
所有权，一简由当前8454音形身份及频率自然竞争产生。

## 验证顺序

1. 静态生成新配置，断言一/二/三码方案各且仅有一条；
2. 以C07完整卡配置为骨架，通过生成器`--mapping-source`显式提取C07结果配置的
   `form.mapping`，做Chai原生编码而不退火；这是因为优化结果配置本身不是完整独立输入；
   核对8454行及简码所有权；
3. 展开一简名单，并与0.7名单对照；
4. 重新跑短冒烟，确认全部核心指标有限且完整；
5. 重新进行必要的参数确认和正式抽卡，不复用0048的排名结论。

## 边界

- 不覆盖0048与0050，保留为bug现场；
- 不加入快符、无理码、谕旨、字词让位或词表；
- 一简恢复后产生的一切结果必须写入新实验目录。
