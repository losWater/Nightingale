# 夜莺重开工程：数据迁移设计

## 目标

在不改动、不删除任何历史资产的前提下，建立与旧脚本、旧中间产物隔离的夜莺重开工程目录。

## 本次迁移范围

1. 复制项目管理文档到 `00_项目管理`。
2. 复制已确定根集到 `01_根集`，标记为待完整性复核的候选权威资产。
3. 复制 8105 字人工阅读拆分表到 `02_规范拆分`，文件名显式标注“待核验”。
4. 旧 `拆分规则.yaml` 仅复制到 `99_历史参考`，不进入新规范拆分的权威输入。
5. 不迁移旧脚本、旧退火配置、旧字音频率和旧退火元素表。

## 输入

- `work/重开工程/工程基线与脚本规范.md`
- `work/重开工程/进度表.md`
- `夜莺B/work/根集.yaml`
- `夜莺B/work/最终规范拆分表_人工阅读.tsv`
- `夜莺B/work/最终规茆分表_人工阅读.html`
- `夜莺B/work/拆分规则.yaml`

## 输出

- 隔离的分层目录。
- 候选根集。
- 8105 字待核验拆分表（TSV/HTML）。
- 只读语义的旧拆分规则参考副本。
- 记录每个迁移文件来源、目标、时间与 SHA-256 的清单。

## 禁止事项

- 不删除、移动或覆盖任何历史资产。
- 不把旧 `拆分规则.yaml` 视为新工程权威规则。
- 不复制任何旧脚本到新工程。
- 不修改根集、拆分内容或字音频率。

## 验收条件

1. TSV 为 UTF-8 BOM，共 8106 行（表头＋8105字）。
2. HTML 声明 UTF-8，且包含 8105 字数量说明。
3. 迁移后文件与来源文件 SHA-256 相同。
4. 新目录不含历史脚本。
5. 所有迁移项均写入迁移清单。
