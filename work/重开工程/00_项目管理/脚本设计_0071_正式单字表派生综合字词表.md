# 脚本设计0071：从正式单字表派生综合字词表

## 目的

以已经实装人工裁决的正式普通单字表为唯一单字事实源，加入60000条二字词和17860条
四字及以上词，生成新的无简词综合字词审查表。不得读取旧C19审计表来决定候选层，
不得重新生成或还原任何单字码位。

## 新分层规则

1. 扫描正式单字表，得到所有存在1—3码入口的字；
2. 单字的1—3码入口均为实际单字入口；
3. 一个字若存在任意1—3码入口，则该字的全部四码入口均为“出简保留全码”；
4. 一个字若不存在1—3码入口，则其全部四码入口均为实际单字入口；
5. 每个四码位固定排列为“实际单字 → 首词 → 出简保留全码 → 其余词”，各层内部保持
   输入顺序；保留全码最多只让出首选，不能被同码的多个词一路压到末尾；
6. 无理码、三码次选和人工换位都只从正式单字表读取，不另作推测。

这一定义按“字”而非旧审计表中的“音字身份”判断。多音字只要已有任一简码，其所有
四码入口都让词，符合已经确认的“有简码的新增全码面对词可无脑次选”原则。

## 输入与输出

- 输入：正式普通单字表、精选60000二字词、精选17860四字及以上词；
- 输出：基础词码表、无简词综合字词审查表、搜狗审查表、字词相撞明细、词词重码明细、
  JSON验证报告和Markdown摘要；
- 旧C19编码审计明细不参与生成。

## 门禁

- 输入单字的每个“字＋码＋候选顺序”在输出中恰好出现一次；
- 输入词每条恰好出现一次，词库规模严格为60000＋17860；
- 每个码位各层内部顺序不变；有词时保留全码必须位于首词之后、其余词之前；
- 普通综合表与搜狗综合表反读后的候选序列完全一致；
- 输出目录必须不存在，禁止覆盖正式单字基线。

## 已知实现风险

- 码位容器使用`defaultdict`时，禁止用下标读取可能不存在的码位；否则“读取”会新增空键并
  污染后续集合交集和碰撞统计。生成器统一使用无副作用的`dict.get`读取。
