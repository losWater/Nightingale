# 夜莺B 精选词库来源调研

目标：汇总多个互补词频来源，清洗并聚合出约 6 万词的精选词库，再划分常用等级。Git 转换版若源自同一语料，只作下载／格式备份，不重复计票。

## 第一梯队：建议作为主要统计来源

### BCC 汉语在线语料库（北京语言大学）

- 官方下载：https://bcc.blcu.edu.cn/download
- 官方帮助：https://bcc.blcu.edu.cn/help.html
- 当前公开总规模约 62 亿字；提供多领域、新闻、文学、口语等频道的字词频下载。
- 多领域为新闻、文学、口语、科技等规模抽样的平衡语料，适合作为书面／综合主基准。
- 口语频道约 2.32 亿字且由对话语料构成，适合作为本土日常口语主基准。
- 建议独立使用：多领域词频、新闻词频、文学词频、口语词频；同源频道之间需控制总权重。

### SUBTLEX-CH

- 论文与官方附件：https://pmc.ncbi.nlm.nih.gov/articles/PMC2880003/
- 基于 6,243 部影视字幕，约 3,350 万词／4,680 万字；词表约 99,121 项。
- 同时提供总次数和出现影片数（contextual diversity），适合作为口语／对白层的重要独立来源。
- 影视翻译腔和题材偏差客观存在，不宜单独决定最终排名。

### Chinese Lexical Database 2.1（CLD）

- 官方下载：https://chineselexicaldatabase.com/download.php
- 48,644 个简体普通话词，含 269 个词汇变量。
- 汇集 LWC 微博、PWC 聊天、SUBTLEX-CH 字幕、SCCoW、Chinese Gigaword、LCMC 等频率指标。
- 论文验证中，LWC 微博频率对现代简体中文词汇加工数据预测最佳；PWC 聊天与 SUBTLEX-CH 也表现较好。
- 适合作为网络日常／口语综合证据，并可直接比较不同语域；但覆盖词数不足 6 万，需要其他来源补足。

## 第二梯队：补充与交叉验证

### wordfreq（中文）

- 项目：https://github.com/rspeer/wordfreq
- 聚合 Wikipedia、字幕、新闻、书籍、Web、Twitter 等来源，提供统一 Zipf 频率。
- 适合补充网络新词与跨领域覆盖；中文数据混合简繁，且部分分词来源来历较弱，应降权使用。

### Leipzig Corpora Collection

- 项目：https://wortschatz.uni-leipzig.de/en
- 以自建抓取与处理管线生成 Web、新闻等语料，提供词频；下载数据有明确使用条款。
- 可作为纯互联网／新闻外部验证来源，需选择具体中文语料版本并核对许可。

## Git 可用转换版（不作为独立语料票）

- SUBTLEX-CH JSON：https://github.com/leonsilicon/subtlex-ch-wf
- BLCU／SUBTLEX 转换说明：https://github.com/MarvNC/yomitan-dict-stats
- 综合词表线索：https://github.com/lxs602/Chinese-Mandarin-Dictionaries

这些仓库方便读取格式或在官方端不可用时备用，但若其数据源已经是 BCC／SUBTLEX，不得再次作为独立来源增加覆盖票。

## 初步组合角色

- 书面／正式主基准：BCC 多领域 + BCC 新闻／文学。
- 本土对话主基准：BCC 口语。
- 影视对白独立基准：SUBTLEX-CH。
- 网络与现代日常校准：CLD 中的 LWC 微博、PWC 聊天。
- 广覆盖补充：wordfreq；必要时加入 Leipzig 中文 Web 语料。

## 合并前必须核对

- 每份数据的许可、更新时间、词条总数、分词方法、原始频率与语料总量。
- 简繁转换、异体规范、数字／英文／符号、专名、词长分布。
- 同源数据去重：CLD 的 SUBTLEX列与原始 SUBTLEX不可当成两份独立支持；BCC Git转换版同理。
- 选词可信度与直接输入频率分别评分，避免专业词或专名因单一来源高频挤入核心层。

## 外来码表与异构格式导入原则

用户提供的许多词库可能是其他输入方案的成品码表。导入时只采集词条本身，源方案编码默认全部丢弃，绝不进入夜莺元素序列、频率或排序字段。

### 原始文件与中间层

1. 原始文件只读保存，不原地改写。
2. 每个来源单独建立适配器和格式说明，记录编码（UTF-8／UTF-8-BOM／GB18030等）、分隔符、列含义、注释规则及是否有表头。
3. 统一输出标准中间表：`词条、来源、源内排名、可信频率、词性／分类、原始行号、清洗标记`。
4. 任何无法确认含义的数字列、编码列、权重列只保留在溯源信息中，不参与综合评分。

### 常见格式处理

- `词条<TAB>编码`、`编码<TAB>词条`：识别方向后仅取词条。
- `词条<TAB>频率<TAB>编码`：只有来源文档明确说明频率含义时才采用频率。
- Rime YAML：解析正文词条列，跳过YAML头、注释和源方案编码。
- 搜狗／QQ／其他二进制词库：先用可靠转换工具导出文本，再进入标准适配器；不得把二进制乱码当词条。
- 无表头多列文件：先抽样检查并形成显式格式配置，不按“第几列大概是什么”批量猜测。

### 清洗与校验

- 规范BOM、换行、全半角、不可见字符和首尾空白；必要时做简繁规范化，但保留原词形供追溯。
- 初选词条必须以汉字为主体；数字、英文、符号、专名和混合串进入单独候选层，不直接混入通用6万词。
- 去除单字（由独立字表负责），检查异常超长词、重复字串、整句、网页碎片和疑似编码串。
- 同一词跨来源合并时保留完整来源集合，不重复计词；同源的不同转载版也只计一票。
- 每个适配器输出抽样报告、有效／拒绝数量和拒绝原因，人工确认后才进入聚合。
