## 1. 当前目标

编码形式为 `abxy`：

- `ab` 是固定的小鹤双拼音码，当前阶段不可调整。
- `x` 是首根，`y` 是末根。
- 中间部件在最终码表中不可见。
- 所以真正的问题是：在一个给定读音下，如何用首根和末根区分同音字。

## 2. 首末根原理

这是整个项目的核心判断方法，简称“原理”。

若一个字的实际拆分为 `x * y`，其中 `*` 是任意数量的中间部件，那么在码表层只留下 `x` 和 `y`。因此：

1. 候选部件若只改变不可见的中间部分，就不会改变全码。
2. 一个较大的部件与一个更小、更熟悉的首根具有相同首端时，往往只保留小根即可。例如虍可拆卜、厂、匕；在虚等字中间部分不可见，所以不必再立虍。
3. 判断末根必须倒着看。不能因为一个大部件视觉上完整，就默认它应整体成为末根；应先确认从字尾向前第一个可见根是什么。曷最终没有整体挂日，而是把末端 `匃` 挂入框家。
4. 若某字不立根后形成 `abxx`，它在码面上等价于自身成根的打法；若合并进一个直观近形家族且不产生碰撞，通常合并更省记忆。
5. 原理只保证首末码面等价，不代表中间拆分可以随意。人工边界仍要符合人眼结构，并防止以后新增根后意外改变首末链。

## 3. 两项正式评价指标

每个候选必须检查全部常用字、全部读音，不能只检查它最初出现的音节。

### 三码简码 `abx`

- 每个音节先排除唯一的二简字 `ab`。
- 剩余字按首根 `x` 分堆。
- 每堆只有最高频的一个字取得三码 `abx`，其他字使用全码。
- 比较候选实施前后：谁新掉出三码、谁获救、是否只是低频字让位。
- 二简字不参与三码位置竞争，脚本已修正这一点。

### 全码 `abxy`

- 同音节且首末根完全相同才算全码重码。
- 必须区分“原本就撞”与“候选新增”。候选只为增量负责。
- 用户可以接受少量低频／零频全码重码，但高频真实撞车优先否决。

### 多音字规则

一个字有多个读音时，所有读音都参与检查。不能用冷门读音没有重码，掩盖常用读音上的碰撞。

当前频率数据把整字总频复制给每个读音，因此会夸大冷门音（例如省 `xing`、万 `mo`、世 `xie`）。看到多音字改变三码归属时必须人工判断真实读音频率，不能照单全收。

## 4. 标准工作流程

### A. 开一个音节

```powershell
$env:PYTHONUTF8='1'
python .\夜莺B\scripts\syl_table.py di
```

先把该音节的全部常用字、首根堆、末根和结构明细列给主人。不要一上来替主人连续裁决多个字。

### B. 发现候选部件

先确认三件事：

1. `根集.yaml` 中是否早已有这个根或附属，不能凭记忆判断。
2. chai 中整字、偏旁形、省形分别叫什么，是否为不同元素。
3. 它有哪些直接首末用户，是否遗漏对应部首和形近字。

常用命令：

```powershell
rg -n "候选字" .\夜莺B\work\根集.yaml .\夜莺B\work\选根台账.md
python .\夜莺B\scripts\chai_lookup.py 候选字 相关字1 相关字2
```

### C. 跑“有根／无根”全字集双检

独立根或单个候选：

```powershell
python .\夜莺B\scripts\candidate_root_check.py "弟"
```

同键合并／主根加附属：

```powershell
python .\夜莺B\scripts\candidate_root_check.py "氏+氐"
```

脚本没有标准 `--help`；传入 `--help` 会被误当作候选根。不要这样调用。

向主人汇报时按以下顺序：覆盖字族 → 三码新增／获救 → 全码新增／解除 → 直观性与根数代价。数据给完即停，等主人裁决。

### D. 主人裁决后落盘

只有主人明确说“加／合并／不加”后，才能把决定写入正式文件：

- `根集.yaml`：主根、附属、锚定关系。
- `拆分规则.yaml`：chai 自动拆分不能表达的人工边界。
- `选根台账.md`：字族范围、决定、理由、三码和全码增量。

新增一个根时必须再次提醒并检查：对应偏旁、部首形、省形和容易遗漏的形近变体。

### E. 重建与审计

```powershell
python .\夜莺B\scripts\build_analysis.py --run
python .\夜莺B\scripts\audit_rules.py
```

确认根元素数量、附属／锚定数量、零就业数、人工边界状态。审计通过后再进入下一个候选。

### F. 音节收官

重新运行 `syl_table.py 音节`，确认所有常用字均已逐项裁决，把收官状态写进台账或本日志。然后才进入下一个音节。

## 5. 已知工具边界与假报告

`candidate_root_check.py` 当前没有带入所有整字序列覆写，因此每次候选检查常重复出现以下假变化：

- 临
- 羲／曦／爔
- 彖／蠡
- 庸／痈、埇／墉、鲬／鳙等庸家族
- 隶／逮

这些并非候选导致，不能记入新增或解除。正式 `build_analysis.py --run` 会应用序列覆写。

另外，chai 自动结构不是最终裁决：它可能跨借笔画、拆散人工定义根，或把独体字落成笔画。遇到反直观结果先查结构树，再决定附属根、人工部件拆分或整字序列覆写。
