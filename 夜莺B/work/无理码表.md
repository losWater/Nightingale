# 夜莺 B 无理码表

无理码用于解除同音、同首根、同末根且无法由排键解决的结构硬碰撞。表中序列参与退火：记录的是根码元，不是最终字母键。

## 使用原则

- 无理码是穷尽立根、归并、拆分调整、键位优化和局部微调之后仍无法解决时的最后手段，不能用来替代正常优化。
- 形码用户有权不接受并删除任意无理码；发布方案必须允许用户删掉全部无理码后继续正常使用。
- 如果一项性能改进依赖无理码才成立，就不计作方案本体的真实优化。核心跑分、重码结论和方案比较必须另行报告“删除全部无理码”的结果。
- 无理码只是一层可删除的兼容／定位方案，不得反向左右字根选择和主体键位布局。

| 字 | 音码 | 强制形码元 | 保留自然码的字 | 原因 |
|---|---|---|---|---|
| 骂 | ma | 口 + 口 | 吗 = 口 + 马 | `吗/骂` 自然拆分均为 `ma + 口 + 马`；用双口提示骂的双口结构 |
| 侯 | hz | 亻 + 竖 | 候 = 亻 + 矢 | `候/侯` 当前首末均为 `hz + 亻 + 矢`；主人裁决以竖作无理末码 |

## 主码与正式发布

- 退火、跑分与验收阶段只使用唯一主码：`骂=口+口`、`侯=亻+竖`。自然碰撞码不参与优化，否则会把已经解除的硬碰撞重新计入。
- 正式发布阶段允许容错码表，把自然拆分恢复为备用码：`骂=口+马`、`侯=亻+矢`。
- 容错码必须排在对应自然主码字之后：`ma+口+马` 下“吗”优先、“骂”后置；`hz+亻+矢` 下“候”优先、“侯”后置。
- 正式版同时保留无理主码，用户既可用零重主码定位，也可按自然直觉输入后选重。
- 主码跑分与含容错码的发布码表必须分开统计，不能用容错重码反推退火失败。
- 同时必须保留“完全删除无理码、恢复自然拆分”的验收口径；该结果才代表方案本体性能。

任何无理码或容错码的新增、迁移、删除都必须在本表登记。
