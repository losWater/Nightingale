# 仓库重构路线图

## 目标

让仓库首页只呈现当前可用的夜莺 0.8.5，让长期有效的原理独立于版本保存，并把源码、真源、派生物、实验现场和历史归档分开。

## 第一阶段：入口与边界（已完成）

- 首页改为 0.8.5 入口，0.4 不再被描述为当前方案。
- 0.1—0.7 发布物移入 `archive/releases/`，当前 `releases/` 只保留 0.8.5。
- 0.4 根目录脚本和旧资产移入 `archive/legacy-v04/`。
- 裸露在仓库根目录的旧运行输出移入 `archive/experiment-runs/root-output/`。
- 建立 `docs/`、`schema/`、`pipelines/`、`apps/` 与 `archive/` 的目标边界。
- 将首末根原理提炼到 `docs/principles/首末根原理.md`。
- 整理 0.8.5 发布目录，并验证正式派生表仍可一键重建。

## 第二阶段：活跃源码归位（下一步）

这一阶段风险较高，必须逐条迁移并保留兼容入口：

1. 把 `work/重开工程/scripts/` 中仍通用的生成器移入 `pipelines/`。
2. 把查询、字根练习、部件查询和必拆字练习的模板移入 `apps/`。
3. 把根集、拆分、字架、读音别名等版本化真源移入 `schema/`。
4. 将旧路径暂时保留为薄包装或自动镜像，逐个消除硬编码绝对路径。
5. 每迁移一组就运行单元测试、0.8.5 重建和发布清单校验。

## 第三阶段：实验现场瘦身

- 为 `work/` 制定“源码、人工裁决、可复现实验清单、可丢弃输出”四类规则。
- 大型退火结果只保留候选、指标、配置、随机种子和生成清单。
- 将 `夜莺B/` 冻结为有明确索引的历史研究阶段；长期原理继续提炼到 `docs/principles/`。
- 完善 `.gitignore`，阻止新的缓存、临时输出和第三方仓库进入版本控制候选。

## 完成标准

- 新维护者从根 `README.md` 能在三次点击内找到正式码表、原理、真源和构建方式。
- 一个概念只有一个维护真源，其余均为生成物、镜像或历史快照。
- 发布流程不依赖个人机器绝对路径。
- 从干净检出可以重建 0.8.5 派生物并通过测试。
- 历史资料可追溯，但不会混入当前入口。
